2 · The tool belt (the agent's hands)
file toolslist_files · read_file · write_files · delete_file — the virtual overlay (SCRATCH = whole project; IMPORT = overlay on the repo)
search_filesregex over file contents → path:line: match — find definitions/usages instead of guessing paths

↔
run_command → Vercel Sandbox (Firecracker microVM) execInSandbox: reuse or create the workspace VM, re-sync files, run sh -c (120s cap) → exit code + stdout/stderr
The Codex loop: write_files → run_command (npm test / build) → read the failure → fix the code → run again — until it passes.
Same per-workspace VM as live preview (helix-run-<id>, 15-min life). Guests blocked; commands cost-bounded.
3 · Background tasks
POST /tasks → after() Creates a WorkspaceTask(queued), returns immediately, then runs the SAME runAgentTurn AFTER the response (next/server after(), ≤5 min).
WorkspaceTaskstatus: queued→running→done|error · stores resultText + changes manifest. Client polls every 5s while non-terminal; up to 3 parallel per workspace.
Zombie sweep: a task running >6 min (platform killed the fn) is marked timed-out on next GET.
4 · Diff & review
GET /diffoverlay vs base (repo file @ pinned branch for IMPORT, "" for SCRATCH) → added / modified / deleted entries
Diff tabMonaco DiffEditor (base ↔ current, read-only) with a status-dotted file list — review exactly what will ship before pushing
POST /reviewone no-tools model call: flags correctness / security / data-loss issues with file:line, ends with a ship/hold verdict — lands in chat history
