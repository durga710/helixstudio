# Security Policy

We take the security of Helix Studio and our users' data seriously. Thank you for
helping keep the platform safe.

## Supported versions

Helix Studio is a continuously deployed product; the **latest version on
`main` / production (helixstudio.org)** is the only supported version. Fixes are
rolled forward, not back-ported.

## Reporting a vulnerability

**Please do not report security issues through public GitHub issues, discussions,
or pull requests.**

Instead, use one of the following private channels:

1. **GitHub Private Vulnerability Reporting** (preferred) —
   open the repository's **Security → Report a vulnerability** tab.
2. **Email** — [security@helixstudio.org](mailto:security@helixstudio.org).

Please include:

- A description of the issue and its potential impact.
- Steps to reproduce (proof-of-concept if possible).
- Affected URLs, endpoints, or components.
- Any suggested remediation.

## What to expect

- **Acknowledgement** within 3 business days.
- A triage assessment and severity rating shortly after.
- Coordinated disclosure: we will work with you on a timeline and credit you
  (if you wish) once a fix is deployed.

## Scope

In scope: the Helix Studio web application, API, and supporting infrastructure.

Out of scope: denial-of-service testing, social engineering, physical attacks,
and findings that require a compromised device or browser. Please act in good
faith, avoid privacy violations and data destruction, and only test against
accounts you own.
