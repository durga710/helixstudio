# Helix Studio — Engineering Audit
**Date:** 2026-06-18 · **Auditor role:** Senior Staff Engineer (joining) · **Repo:** `helixstudio-deploy` @ `main` (clean working tree, 240 commits)
**Method:** Git history analysis + 5 parallel code deep-dives (AI/agent, editor/desktop, education, backend/security, frontend/debt). Every claim traced to source — names were not trusted.

---

## 1. Executive Summary

**The biggest finding is a framing mismatch.** The audit brief describes Helix Studio as a desktop AI IDE "like Cursor, Windsurf, VS Code." **The actual product is a web-first AI coding *and* education platform** — a Next.js 16 app with a Monaco editor, an AI agent that builds apps in cloud sandboxes, and a genuinely substantial classroom/lessons system. The "desktop app" is a thin Electron shell wrapping the web app, and its native-integration bridge is **dead code**.

Against that *real* identity, the product is surprisingly mature and mostly **real, not faked**: real multi-provider LLM calls, real Stripe billing, production-grade auth, a 40-model PostgreSQL schema, real git push, and an education platform (interactive ML "studios," AI-generated lessons, spaces/assignments/gradebook) that all persists to the database.

The serious gaps are **engineering hygiene and honesty**, not missing features: **zero automated tests**, two ~1,500-line god components, a fully **scripted marketing demo** and **fabricated testimonials** with the disclaimer buried only in a code comment.

**Overall progress:** ~**65–70%** toward a credible v1.0 of *what it actually is*; ~**35%** toward the "Cursor-style desktop IDE" framing. Recommend: pick one identity (recommendation: **AI-assisted coding-education platform**), and harden before shipping.

## 2. Architecture Overview

- **Framework:** Next.js 16.2.9 (App Router), React, TypeScript, Tailwind (CSS-variable design system).
- **Auth:** NextAuth v5 beta — Credentials (scrypt) + GitHub + Google OAuth; JWT sessions revalidated against DB every 60s.
- **DB:** PostgreSQL via Prisma 7 (generated client committed under `src/generated/prisma`). 40 models. Falls back to in-memory "demo mode" if `DATABASE_URL` is unset.
- **AI:** `src/lib/ai/**` — provider abstraction over Anthropic (default), OpenAI, Gemini (OpenAI-compat), and local/OSS (Ollama/vLLM). Real token streaming. BYOK via httpOnly cookie → platform env keys (admin only).
- **Execution:** Vercel Sandbox (Firecracker VMs) for build/verify/run; local dev runner spawns dev servers; files live as a **DB-backed virtual filesystem** (`WorkspaceFile`), exported to a temp dir to run.
- **Editor:** `@monaco-editor/react` (real), DB overlay model with intent ledger + undo.
- **Billing:** Stripe — checkout, portal, signature-verified webhooks, server-side plan/quota enforcement.
- **Desktop:** `desktop/main.js` — Electron `BrowserWindow` booting a bundled standalone Next server (falls back to helixstudio.org). Native shell/file IPC exists but is **never called**.
- **Surface area:** ~90 API routes, 403 TS/TSX files (~130k LOC incl. generated; generated Prisma is a large share).

## 7. Technical Debt

- **Zero automated tests** — 0 `.test`/`.spec` files; one smoke script (`npm run test:studios`). Single largest risk.
- **God components** — `workspace-panel.tsx` (1,742 lines) and `chat-panel.tsx` (1,467 lines) fuse editor, tree, diff, preview, dialogs, ledger, task runner, model picker.
- **Logging** — ~32 ungrouped `console.*`; no structured logger.
- **Duplicated inline Tailwind** — `btnSolid`/`btnGhost`/`fieldInput` repeated across pages instead of shared components.
- **Type debt** — modest: ~4 meaningful `: any` in hand-written lib (most repo-wide hits are in generated Prisma).
- **No image optimization** — `<img>` everywhere, no Next.js `Image`.
- **Committed generated client** — large `src/generated/prisma` in tree inflates diffs.
- **Rate limiting in-memory per instance** — resets per server on horizontal scale (Redis noted as TODO).

## 8. Bugs / Risks

- **~~HIGH~~ → CORRECTED (non-issue):** A first-pass review flagged the Stripe webhook as trusting client-supplied `metadata.userId`/`spaceId`. **On verification this is false.** Both checkout routes set the IDs server-side from the authenticated session (`api/billing/checkout/route.ts:58` uses `g.user.id`; `api/spaces/[id]/billing/checkout/route.ts:42,71-72` verifies owner + sets `space.id`), request bodies carry only `{ tier }`/`{ seats }`, and the webhook verifies the Stripe signature (`api/billing/webhook/route.ts:42-46`). No client-controlled ID reaches the handlers. Optional defense-in-depth only: cross-check `sub.customer` against the stored `stripeCustomerId` (low value; risks the documented first-event race).
- **MEDIUM — User LLM API keys stored plaintext in DB** (`prisma/schema.prisma:286-289`). A DB breach exposes all keys; add app-level/Vault/DB encryption.
- **MEDIUM — Per-instance rate limits** (`api/auth/signup/route.ts:36`).
- **MEDIUM — Admin bootstrap** — empty `ADMIN_EMAILS` denies all admins; new prod deploys can't bootstrap without documentation (`src/lib/admin.ts:17-22`).
- **LOW — Guest builds abandoned on disconnect** — only premium gets background `after()` persistence (`api/chat/route.ts:106-113`).
- **LOW — Admin actions logged to stdout**, not an audit table (`AuditEvent` model exists but underused).

## 11. Security Review

Production-grade core (scrypt, JWT revalidation, layered ownership/role guards, verified Stripe webhooks, no hardcoded secrets, BYOK in httpOnly cookie). Ranked concerns: **MEDIUM** plaintext key storage, per-instance rate limits, admin bootstrap; **LOW** guest build loss, stdout audit. (The earlier "HIGH webhook metadata trust" finding was withdrawn on verification — see §8.) No SQL injection risk (Prisma), pre-push secret scanning is a nice touch.

## 12. Performance Review

No glaring N+1s; routes batch with `Promise.all` and bound result sets (workspaces ≤50). Wins available: stream agent tool-step deltas (currently batched → perceived hangs), adopt `next/image`, move rate limiting/caching to Redis, lazy-split the two god components to cut editor bundle.

## 18. Final Recommendation

Helix Studio is **further along and more real than the codebase's scariest signals (0 tests, mock-keyword grep hits) suggest** — the agent, billing, auth, and education systems genuinely work. Three things hold it back from being shippable with a straight face: **(1) an identity split** between "desktop IDE" marketing and a "web coding-education platform" reality, **(2) zero test coverage** under two giant components, and **(3) honesty gaps** in the demo/testimonials that are a real reputational risk if shown to VCs or customers without visible disclaimers.

**Recommendation:** commit to the **AI-assisted coding-education platform** identity (it's the strongest, most differentiated, most-built part), label all illustrative content honestly, land a test/CI safety net this week, and treat "desktop IDE" features (terminal, native integration, inline completion) as an explicit, scoped v0.2+ bet rather than implied-already-built.
